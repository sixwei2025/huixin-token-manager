# v1.0.0 验证范围

2026-11-13，Apple Silicon 本机验证。编译目标为 macOS 14+；没有将 Windows 或 Intel Mac 列入支持范围，也没有在每一种 M 系列芯片和每一个系统小版本上实机测试。

- SwiftUI 原生程序编译、临时签名及严格签名检查通过。
- 使用从官方 v0.84.0 下载并通过固定 SHA-256 校验的 CodexBar 引擎，不依赖原应用路径。
- 真实响应形状的匿名样本检查通过：Codex 剩余百分比、Antigravity 双模型周期、Grok Bot 独立字段、WorkBuddy 总积分与可用积分、缺少独立字段时拒绝混用、缓存不保留账号字段。
- 移走原 CodexBar 应用并停止其进程后，内置引擎可启动，Codex / Antigravity 实时读取成功。
- Grok Bot / WorkBuddy 的打包后读取提示需要本机浏览器钥匙串授权；已增加用户主动点击的“连接浏览器”入口。授权完成后的读取取决于使用者本机登录和系统权限，本次未代替用户处理新的钥匙串授权，不声称所有新机器都免授权即用。
- 原生界面已核对四卡布局、模型标签、WorkBuddy 双积分、来源说明与连接按钮；公开截图使用真实应用的演示模式，清楚标注演示数据。
- 源码与安装包目录扫描未发现作者账号标识、密码、Cookie、登录文件或额度缓存。

后续反馈请提供应用版本、系统版本、工具名和不含隐私的通用错误。不要上传原始登录文件或完整接口响应。

## v1.0.2 现场修正

标准应用包注册信息已补齐（APPL、平台、主类等）；沿用旧版应用标识 cn.huixin.quotamanager，保持升级兼容。系统菜单栏“允许显示”列表已出现本应用且开关打开，用户亲自确认图标已出现并可点击。

浏览器来源改为同一常驻桥接进程，按上游临时签名保护策略只在进程内保留已验证会话。针对本机 Swift 发行构建的 TaskLocal 观察器崩溃，应用一个单函数不优化标注；授权和拒绝规则没有删除或放宽。连接后真实验证通过：WorkBuddy 连续两次后台读取成功，Grok Bot 连接和独立额度后台读取成功。

正式安装版进一步验证：在同一读取进程内先连接 WorkBuddy，再连接 Grok Bot，两者交叉刷新成功；随后连续多轮每分钟自动刷新均成功，界面不再标记旧数据。用户确认已将 Token 管家与技能管家两个图标放在一起。关闭独立窗口后主程序和读取进程继续运行。
